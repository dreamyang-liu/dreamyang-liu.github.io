    Model Quantization

    Quantization is a technique used to reduce model size and speed up inference. The core idea is to convert model weights from a higher-precision data type such as FP32 to a lower-precision data type such as FP16/INT8.
    There are also more aggressive quantization approaches, like quantizing weights down to INT4, or even binarization — BitNet is a prime example of how far this can go.

    One thing worth noting: quantizing to INT8 and FP8 are not the same thing. INT8 is an integer type, while FP8 is a floating-point type; they have different representable ranges and precision. In general, INT8 offers better throughput — integer arithmetic is faster and more power-efficient than floating-point arithmetic — but its representable range is narrower.

    There are both upsides and downsides to quantizing a model.

    Benefits

    1. Reduced model size: A quantized model occupies less memory, loads faster, and has a smaller memory footprint.
    2. Faster inference: A quantized model can run on faster hardware. On a GPU, for example, quantized models can perform matrix multiplications more quickly.
    3. Lower power consumption: A quantized model can run on lower-power hardware, such as mobile devices, and can sustain longer operation.

    Drawbacks

    1. Accuracy loss: A quantized model may experience some accuracy degradation, especially when quantizing to INT8, where the loss can be significant.
    2. Added complexity: Quantization may introduce additional computation, such as the quantize and dequantize steps, which increases the overall complexity of the model.

    Here is some additional context on PTQ and QAT:
    Post-Training Quantization (PTQ)

    • Definition: After training is complete, use a small calibration dataset (typically a few hundred to a few thousand samples) to compute quantization parameters (scale, zero-point) for each layer’s weights and activations, then convert the floating-point model to a low-bitwidth integer model.
    • Pros:
      • Fast, no retraining or fine-tuning required
      • Straightforward to implement, suitable for resource-constrained scenarios
    • Cons:
      • Higher quantization error, especially noticeable for sensitive layers or small models
      • Not robust to asymmetric or long-tail distributions

    The Role of the Calibration Set

    The calibration set plays several key roles in static quantization:

    1. Estimating activation distributions:

      • Run one forward pass of the model over the calibration set, letting Observers collect numerical statistics at each node.
      • These statistics are used to compute optimal quantization parameters downstream.

    2. Determining quantization parameters:

      • Use the collected statistics to compute scale and zero-point.
      • Methods such as Min-Max or histogram-based approaches can be used to balance accuracy and dynamic range.

    3. Representative samples:

      • The calibration set should cover typical inputs for the target application to ensure the quantized model performs well in real-world scenarios.
      • Usually 100–1000 samples suffice, balancing statistical stability against calibration time.

    4. Static vs. dynamic quantization:

      • Static quantization requires a calibration set but yields faster inference.
      • Dynamic quantization requires no calibration, but must compute activation quantization parameters at each inference step.

    Quantization-Aware Training (QAT)

    • Definition: Introduce quantization simulation (FakeQuant) operators during training or fine-tuning so that the model simulates low-precision arithmetic in the forward pass while continuing to update parameters in the backward pass, allowing it to adapt to quantization-induced error.
    • Pros:
      • Can significantly recover or even exceed PTQ accuracy
      • More friendly to complex distributions and custom strategies
    • Cons:
      • Requires additional training or fine-tuning overhead (1–5 epochs)
      • More complex to implement, as it requires inserting FakeQuant layers into the training framework

    Current Research

    LLM-Specific PTQ Methods

    • GPTQ performs one-shot weight quantization based on approximate second-order information, enabling 3–4-bit quantization of a 175B-parameter model on a single GPU with almost no accuracy loss.
    • AWQ uses activation-aware per-channel scaling to protect only 1% of salient weights, dramatically reducing quantization error and enabling efficient 4-bit compression and acceleration on multimodal LLMs.
    • SmoothQuant migrates activation outliers to weights offline to achieve W8A8 PTQ, delivering up to 1.56× speedup and 2× memory reduction on LLMs.
    • The latest SmoothQuant+ pushes PTQ to 4-bit group-wise weight quantization for near-lossless LLM deployment.
