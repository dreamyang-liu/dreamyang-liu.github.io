Tree DP

2026-06-02
Dynamic Programming Trees

One sentence: one DFS pass, and each node’s answer = subtree aggregate + its own contribution. At its core it’s post-order traversal + state propagated on nodes, returning bottom-up.

Intuition — Post-order DFS + Subtree Aggregation

Linear DP reads state from the left; tree DP reads state from the subtree below. In other words, trees don’t need a new algorithm — you just replace “the previous state” with “the return values of all child nodes.”

The core pattern boils down to one sentence:

Write a dfs(node) that recursively post-orders both children, combines their return values, then returns the result to the parent.

When we reach node u, we already have the results of dfs(u.left) and dfs(u.right). We need to decide two things:

  1. What does the current node contribute (update the global answer, or fold it into its own state)
  2. What does it return upward (what information about my subtree does the parent need to continue)

These two things are often different. The animation below demonstrates this most clearly with the binary tree diameter (LC 543): the “path through me” that updates the global answer is left-chain + right-chain, but the “chain extending upward” that gets returned can only go one way — because a path can’t branch at the parent.

Follow the post-order in the animation: leaf 4 → leaf 6 → node 5 → node 2 → leaf 3 → root 1. Each time a node is visited, the blue ↑ is the depth it returns to its parent, green is the longest path passing through it, and the red global ans is only refreshed when needed. Once you’ve watched this, every template below is just the same skeleton.

Three things you must think through before writing a single line:

  1. What does an empty node return — this is the base case. Usually 0 or (0, 0), but some problems (like maximum path sum) need -inf.
  2. How many states go in the return tuple — single state (depth) / two states (take vs. skip) / more (binary tree cameras uses 3).
  3. Is this node’s contribution local or global — “the path passing through me” updates the global ans; “the chain extending to me” is what gets returned upward. Never mix the two.

Advanced: Rerooting DP (Two-Pass DFS)

The templates above assume a fixed root. If the problem asks for “the answer when each node is the root” (e.g. LC 834 Sum of Distances in Tree), brute-forcing a DFS from every node is .

Rerooting DP uses two DFS passes:

  1. First DFS (post-order): fix node 0 as the root and compute dp[0].
  2. Second DFS (pre-order): propagate downward, incrementally updating dp[child] = dp[parent] + delta.

The key insight is figuring out “when we reroot from parent to child, what is the incremental change?” It’s generally an formula, giving total time.

Memory Aid / Common Mistakes

One-sentence mantra: post-order recurse both children, pack results into a tuple and return upward, update global answer along the way.

Three points people get wrong repeatedly:

  1. Updating the global answer vs. returning to the parent are two separate operations — in diameter / maximum path sum problems, if you return the “bent path” upward, the parent sees a fork and everything goes wrong.
  2. The identity element for empty nodes — when maximizing and node values can be negative, don’t reflexively return 0; see LC 124 for negative-contribution clipping.
  3. The skip case — when skipping the current node, children can be taken or skipped freely, so use max(L), not L[1]. Nearly everyone steps on this bug the first time they write House Robber III.

Decision cheat sheet:

  • “Longest path / diameter on a tree” → subtree aggregation, return one extending chain.
  • “Select nodes with no parent-child pair” → take/skip, return a tuple.
  • “Answer for each node as root” → rerooting DP, two DFS passes.

Exercises

1. Why does tree DP use post-order traversal? Can pre-order work?

Post-order means “process children before processing the current node.” A node’s answer depends on its children’s return values, so post-order is required. In pre-order the children haven’t been computed yet, so there’s nothing to combine. The one exception is the second DFS in rerooting DP, which propagates the parent’s information down incrementally — that pass uses pre-order.

2. Why can't you mix "the path passing through me" with "the chain extending to me"?

“Path through me” = left chain + me + right chain — an upside-down V that can be the global optimum. “Chain extending to me” = max(left, right) + me — a straight line. The difference is that a path can bend at me, but what I pass to my parent cannot bend, otherwise the parent sees a fork, and the grandparent gets even more confused.

3. Why does rerooting DP only need two DFS passes?

The first DFS establishes the baseline “rooted at node 0.” Rerooting from parent to child involves exactly one topological change: the child’s subtree moves from “below the parent” to “above the parent.” The delta is computable, and we propagate it top-down in pre-order, for total work.
