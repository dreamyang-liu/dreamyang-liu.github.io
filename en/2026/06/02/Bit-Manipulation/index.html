Algorithm Bit Manipulation

Rarely shows up in interviews, but when it does, it’s pure memorization. Learn these cold and they’re free points.

5 Must-Know Operations

Operation Meaning
n & 1 Get the lowest bit (check odd/even)
n >> 1 Right-shift by one (divide by 2)
n & (n-1) Clear the lowest set bit
n & -n Extract the lowest set bit (lowbit)
n ^ n == 0 XOR of a number with itself is 0

Three Core Properties of XOR

  • a ^ 0 = a — any number XOR 0 equals itself
  • a ^ a = 0 — any number XOR itself equals 0
  • Commutative and associative — order doesn’t matter, grouping is flexible

Put these three together: XOR a bunch of numbers and all pairs cancel out, leaving only the unpaired one.

Use an integer mask to represent which elements in a set have been selected. A 1 at bit i means element i is included.

Think-It-Through Questions

Why does n&(n-1) clear the lowest set bit? Explain from a binary perspective.

Say the lowest set bit of n is at position k. Then bits 0 through k-1 of n are all 0, and bit k is 1.

What n-1 does: bit k becomes 0, and bits 0 through k-1 all become 1 (due to borrowing).

So n & (n-1): bit k gives 1&0=0 (cleared!), bits 0 through k-1 give 0&1=0, and all higher bits are unchanged.

Why is state compression DP only suitable for n<=20?

The number of states is 2^n. At n=20 that’s 1 million states — just barely manageable. At n=25 it’s 33 million, at n=30 it’s 1 billion — both memory and time blow up. In practice, interview problems usually cap at n<=16; n=20 is the extreme limit.

In "find two numbers that appear only once," why does lowbit split the two numbers into different groups?

xor_all = a ^ b. The lowbit extracts the first bit where a and b differ. At that bit, a is 1 and b is 0 (or vice versa). Partitioning by that bit guarantees a and b end up in different groups. All the other paired numbers have both copies in the same group, so they XOR away.
