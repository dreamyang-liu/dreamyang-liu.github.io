Intuition — Discard “Elements That Can Never Be the Answer”

Brute-force sliding window max: rescan k elements on every move, . The waste comes from repeatedly looking at numbers that are already “dominated” and will never get a turn.

Consider [1, 3, -1, ...], window k=3. When the new element 3 arrives, does 1 still matter? While 3 is alive in the window, 1 is always smaller than 3 and will never be the maximum; once 3 expires, 1 will have expired long before. So 1 can be discarded immediately — the earlier the better.

That’s the entire philosophy of the monotonic queue:

  • Enqueue from the tail: when new element x arrives, pop all tail elements <= x (they’re permanently dominated by x).
  • Read the answer from the head: after maintaining monotonicity, the head is always the current window maximum.
  • Expire from the head: if the head’s index has slid out of the window, popleft.

Since both ends need to be operated on, the underlying structure is a deque (double-ended queue), not a plain stack or queue. Each element enters once and leaves once, amortized , total .

Key insight: the queue holds not “all elements in the window” but the candidates that may still become the maximum in the future — a strictly decreasing stack.

Three common mistakes:

  1. Store indices, not values. The expiry check q[0] <= i - k requires the index.
  2. Order matters. Enqueue must come after tail cleanup (otherwise the new element might clean itself out); reading the answer must come after all cleanup.
  3. For minimum, change <= to >= — the queue becomes non-decreasing, everything else stays identical.

Three-step mantra: ① clean the tail of defeated elements → ② enqueue → ③ clean the head of expired elements → ④ read answer from the head.

Monotonic Stack vs. Monotonic Queue — One Word of Difference

Both use monotonicity to discard useless elements; the difference is whether there’s a window constraint.

Dimension Monotonic Stack Monotonic Queue
Structure Stack (one end) Deque (two ends)
Solves Next greater/smaller element Sliding window extremum
Scope Looks arbitrarily far ahead Fixed window k
Head operation Not needed Expire outdated entries
Answer location Determined at pop time Always at the head
Complexity

One line: a monotonic stack is a monotonic queue with infinite window size. The extra “head cleanup” step is the price paid for the window constraint.

Memory Aid

One sentence: those who can outshine you will never let you shine; those who wait for you will have already expired.

Three standard moves:

  1. New element enters from the tail; pop all smaller tail elements (tail fights)
  2. If the head’s index is expired, popleft (head retires)
  3. Head is the window extremum (head collects the prize)

Quick lookup:

  • Only asking “next greater element” → monotonic stack
  • Windowed extremum → monotonic queue
  • Mixed updates / arbitrary range extremum → segment tree or sparse table

One image to remember: a strictly decreasing lineup of candidate kings stands in the deque; the head wears the crown — expire to yield, overpower to enter.
