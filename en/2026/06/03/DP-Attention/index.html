DP Attention: Eliminating KV Cache Duplication

2026-06-03
dp-attention kv-cache expert-parallel moe mlsys

In MoE large-model inference, the conventional TP + EP approach causes every GPU to hold a complete copy of the KV Cache, leading to severe memory redundancy. DP Attention eliminates this redundancy entirely by having each GPU handle only its own requests. This post compares the two approaches (4 GPU, 8 Expert example) with interactive animations.

Conventional approach: TP (Attention) + EP (Experts)

In the conventional approach, Attention uses Tensor Parallelism (each GPU computes 1/N of the heads), and Experts use Expert Parallelism (each GPU holds a subset of Experts). The problem: every GPU must hold a complete KV Cache for all requests — N-fold redundancy.

The animation below shows the full flow for one layer in the conventional approach: initial KV Cache redundancy → Attention (TP) + AllReduce → All-to-All dispatch → Expert computation → All-to-All combine:

Communication overhead per layer:

  • Attention communication: AllReduce (2× per layer, merging partial head results)
  • Expert communication: All-to-All (2× per layer, dispatch + combine)
  • KV Cache: every GPU stores KV for all requests → EP/TP redundant copies

DP Attention: DP (Attention) + EP (Experts)

DP Attention switches Attention to Data Parallel: each GPU handles one request and independently computes the full Attention (all heads) by itself. The Attention parameters are replicated on every GPU, but Attention parameters are very small (~1% of the model), so the cost of replication is negligible.

Key benefit: each GPU only stores the KV Cache for its own request — zero redundancy — and the Attention phase requires zero cross-GPU communication.

The animation below shows the DP Attention approach: initial zero-redundancy KV Cache → Attention (DP, zero communication!) → All-to-All dispatch → Expert computation → All-to-All combine:

Notice the contrast: compared to the conventional approach, DP Attention has no communication at all during the entire Attention phase — one layer is left with only the 2× All-to-All for Experts, and no AllReduce whatsoever.

Comparison summary

Metric ❌ Conventional TP + EP ✓ DP Attention + EP
Attention communication AllReduce (2× per layer) Zero! (each GPU computes independently)
Expert communication All-to-All (2× per layer) All-to-All (2× per layer)
KV Cache copies EP/TP copies (redundant!) 1 copy (zero redundancy)
Total KV Cache size × EP/TP factor Minimized
Attention parameters Sharded by TP Replicated per GPU (~1% of params)

Core trade-off: DP Attention trades “replicating a small slice of Attention parameters” for “eliminating KV Cache redundancy + eliminating Attention communication”. In MoE models, the KV Cache is typically the dominant memory cost during inference, making this trade-off extremely worthwhile — which is why models like DeepSeek-V2/V3 use DP Attention at inference time.
