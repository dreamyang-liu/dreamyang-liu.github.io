Dijkstra's Shortest Path Algorithm

2026-06-02
Graph Theory Shortest Path

Dijkstra = BFS + greedy. Swap the FIFO queue for a priority queue, and at each step pick the unvisited node with the smallest known distance to relax its neighbors. One precondition: non-negative edge weights — because once a node’s distance is finalized, we never revisit it.

Intuition — Why “BFS + Greedy”

BFS is correct on unit-weight graphs: expand layer by layer from the source, and the first time you reach a node is the shortest path. This works because FIFO guarantees “earlier enqueued means smaller distance.”

What about unequal edge weights? Upgrade the queue to a priority queue (min-heap) and still pull out the node with the smallest current distance each time. That node’s distance is then finalized forever — anyone trying to reach it via a detour can only be farther (since all edge weights ≥ 0). That’s where the greedy insight comes from.

One-liner: “pick the nearest unfinalized node, relax its neighbors.” That’s the whole algorithm.

Why Negative Edges Break It

The greedy foundation is “finalized nodes are never updated again.” Once a negative edge exists, a longer-looking path might actually be shorter, and a distance we already finalized could be invalidated. Counter-example:

Starting from A, Dijkstra pops B first and finalizes dist[B]=1, then never looks at B again. But the true shortest path is A→C→B = 5 + (-10) = -5. The algorithm has already moved on and can’t go back.

All weights 1 → plain BFS. Weights 0/1 → 0-1 BFS (deque). Negative weights → Bellman-Ford / SPFA.

Animation — Walk Through the Heap Pops

The animation below starts from node 0. Focus on two things:

  1. Which node is popped at each step — it is always the minimum in the current dist array among unfinalized nodes.
  2. Which cells turn yellow after relaxation — only when “new distance < old distance” is an update applied; updated nodes are pushed back into the heap.

After watching once, compare it against “BFS expanding layer by layer”: Dijkstra does not go by layers — it finalizes nodes in ascending order of known distance.

Template — Python with heapq

Three key implementation details:

  1. Store (distance, node) in the heap — tuple comparison starts from the first element, so it automatically sorts by distance.
  2. if d > dist[u]: continue — the heap may contain multiple stale entries for the same node (Python’s heapq doesn’t support decrease-key, so we just push again). This line skips outdated entries; correctness holds without it, but skipping prevents a lot of wasted relaxation.
  3. Update dist[v] before pushing — don’t “push first, check later”; that causes the heap to blow up.

Variants — Different Skins, Same Skeleton

Variant Change When to use
A* Heap key becomes g(n) + h(n), where h is a heuristic estimate to the goal Single-source single-target with geometric/distance prior, e.g., game pathfinding
Bidirectional Dijkstra Run Dijkstra from both source and target, meet in the middle Single-source single-target, prune large amounts of irrelevant search
0-1 BFS Weights only 0/1; replace heap with deque — weight-0 edges to front, weight-1 to back 0/1 weights,
Layered graph / state expansion Nodes become (node, state), e.g., remaining free passes State affects transition cost
Bellman-Ford No heap; V rounds of relaxing all edges Negative weights,
SPFA Queue-based Bellman-Ford, faster on average Negative weights, sparse graphs

Remember the skeleton: “what data structure maintains the frontier” — FIFO is BFS, min-heap is Dijkstra, deque is 0-1 BFS, scan-all is Bellman-Ford.

Mnemonics / Common Pitfalls

Mnemonic: one sentence — “pick the nearest unfinalized node, relax its neighbors.” Whenever you see “non-negative weights + single-source shortest path,” your reflex should be heapq.

Common pitfalls:

  • Not skipping stale entries: omitting if d > dist[u]: continue causes TLE.
  • Negative weights: see a negative edge, switch to Bellman-Ford immediately — don’t force Dijkstra.
  • Path weight is not a sum: for max-of-edges problems like 1631, use max(d, w) instead of d + w during relaxation. Keep the template flexible.
  • State needs expansion: constraints like “K free passes” or “time limit” require nodes to become tuples.
  • Max-heap: Python’s heapq is a min-heap; push negative values to simulate a max-heap.

Exercises

Why can't Dijkstra handle negative-weight edges? Give a counter-example.

It greedily “finalizes” the node with the current minimum distance and never updates it again. If a subsequent negative edge could shorten an already-finalized node’s distance, there is no way to go back. Counter-example: A→B(1), A→C(5), C→B(-10); starting from A, the algorithm finalizes dist[B]=1 first, but the true shortest path A→C→B = -5 is never found.

What happens if you omit if d > dist[u]: continue?

The heap may contain multiple stale entries for the same node (because heapq doesn’t support decrease-key). Without skipping stale entries, correctness is unaffected, but the algorithm uses outdated distances to relax neighbors, doing a huge amount of wasted work, and complexity degrades.

Why is 0-1 BFS faster than Dijkstra when edge weights are only 0 or 1?

Using a deque: weight-0 edges go to the front, weight-1 edges go to the back. Each node is enqueued at most twice; no heap comparisons means no log factor — vs Dijkstra’s .
