Heap / Priority Queue

2026-06-02
Data Structures Heap

In one sentence: a heap is a complete binary tree expressed implicitly via array indices. It looks like a tree; in memory it is flat. Each operation gets you the current min/max in O(log n); building the heap takes only O(n).

Intuition — A Complete Binary Tree Expressed as an Array

The essence of a heap is not “a special kind of tree” — it is an array plus one index rule:

  • The parent of node i is at (i-1)//2
  • The left and right children of node i are at 2i+1 and 2i+2

No pointers, no node objects. The tree structure is computed entirely from indices. The cost is that a heap must be a complete binary tree (packed tightly from left to right), so the array has no holes.

This rule gives three properties that map directly to all heap operations:

Operation How it works Complexity
push Append to the end of the array, float up toward the parent (sift-up) O(log n)
pop Remove heap[0], move the last element to position 0, sink down toward children (sift-down) O(log n)
heapify sift-down from the last non-leaf node backward, Floyd’s algorithm O(n) not O(n log n)

Min-heap invariant: every node ≤ its two children. Note this only orders parent–child pairs — siblings are unordered — so you cannot use a heap to retrieve the k-th element after sorting; you have to pop repeatedly.

Template — Python heapq Basic Operations

Python’s standard library heapq is a min-heap only. Want a max-heap? Store -x. This is the most common gotcha in interview problems.

If heap elements are tuples, they are compared lexicographically. For objects that are not directly comparable (e.g., linked-list nodes), add a monotonically increasing counter to break ties: (val, idx, node).

4 Canonical Use Cases

Heaps in algorithm problems almost exclusively solve these four things. Recognizing the pattern matters more than writing the code.

1. Top-K — Min-Heap for Largest, Max-Heap for Smallest

To find the K largest elements, use a min-heap of size K; the heap top is the “threshold.” A new element enters only if it exceeds the threshold. Conversely, to find the K smallest, use a max-heap.

Time O(n log k), space O(k). Better than sorting O(n log n) for data streams.

2. Streaming Median — Two Heaps Back to Back

lo is a max-heap (holds the smaller half), hi is a min-heap (holds the larger half). Maintain |len(lo) - len(hi)| ≤ 1; the median is always at the two heap tops.

Key trick: blindly push to lo first, then move one element to hi — this guarantees the invariant lo ≤ hi.

3. Merge K Sorted Lists — Store a Pointer per List in the Heap

Take the smallest current element from each of the K lists/arrays and push them into the heap. Pop the minimum, then push the next element from that list. Each step is O(log K).

Total time O(N log K), where N is the total number of elements.

4. Dijkstra — Heap-Optimized Shortest Path

Naive Dijkstra is O(V²). Using a min-heap keyed by distance to pick the next node brings it down to O((V+E) log V). Store (dist, node) in the heap; when popping, skip the entry if dist > dist[node] (lazy deletion).

Lazy deletion keeps the amortized complexity at O(log n): each element is pushed at most once and skipped at most once, each O(log n).

Memory Aids

Think of a heap in two layers and you will never forget it:

  1. Physical layer: heap = array + index rule parent=(i-1)//2, children=2i+1, 2i+2. All “tree” operations ultimately reduce to arithmetic on array indices.
  2. Invariant layer: a min-heap only guarantees parent ≤ children — siblings are unordered. So a heap can only repeatedly give you the extremum; it cannot give you the “second largest.”
  3. Pattern layer: reflexively reach for a heap when you see these keywords:
    • “Top K / K-th largest / K-th smallest” → Top-K (one heap)
    • “Streaming median / sliding window median” → dual-heap back-to-back
    • “K-way / K sorted” → K-way merge
    • “Shortest path / minimum-cost expansion” → Dijkstra / weighted BFS variant

On the Python side, just remember three calls: heappush / heappop / heap[0], negate for a max-heap, and heapify is O(n).

Exercises

Why does Top-K use a min-heap rather than a max-heap?

A min-heap’s top is the minimum value, so you can quickly tell whether a new element is larger than the current K-th largest. With a max-heap the top is the maximum, and you have no efficient way to evict the smallest element. The min-heap guarantees the heap always contains the K largest elements, with the top acting as the “threshold.”

In the dual-heap approach, why does "push to lo first, then move to hi" guarantee lo ≤ hi?

We push to lo (max-heap) first, then move lo’s maximum to hi (min-heap). This guarantees the element transferred from lo to hi is greater than or equal to all remaining elements in lo. Therefore lo’s maximum ≤ hi’s minimum, i.e., every element in lo ≤ every element in hi.

Why is Floyd heapify O(n) rather than O(n log n)?

Pushing one by one is O(n log n): each sift-up is at most log n. Floyd heapify sifts down from the last non-leaf node backward. The leaf layer (n/2 nodes) does nothing; the second-to-last layer sinks at most 1 step; the layer above that at most 2 steps… Summing Σ (n/2^(h+1)) · h converges to O(n). Intuition: most nodes are near the bottom and barely need to move.

Why doesn't "lazy deletion" in Dijkstra blow up the complexity?

Each edge can push its target node into the heap at most once, so the heap holds at most O(E) entries. Each entry is either processed validly or skipped by the d > dist[u] check — both cases cost O(log E). Total complexity O((V+E) log V), consistent with the theoretical bound.
