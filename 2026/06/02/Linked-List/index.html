链表核心操作

2026-06-02
  • Algorithm
  • 数据结构
  • 链表

三个救命法宝：dummy、画图、改指针前先存好下一个。

6 个核心操作

  1. 反转链表 — prev/cur 双指针，口诀：存、转、移（存 nxt → cur.next=prev → prev=cur, cur=nxt）
  2. 找中点 — 快慢指针，slow 一步 fast 两步，fast 到尾时 slow 在中间
  3. 判环 + 找入口 — Floyd：快慢指针相遇后，一个回起点同速走再次相遇即入口
  4. 合并两个有序链表 — dummy + tail，比较后接上小的
  5. 删除倒数第 N 个 — dummy + 快慢指针拉开 n 步
  6. K 个一组反转 — 先数 k 个，反转区间，递归/迭代拼接

不写错要点

  • dummy 是金科玉律 — 头节点可能被删/换时，用 dummy 统一处理
  • 画图画图画图 — 不画图直接写指针操作 = 必错
  • 空指针检查顺序 — 先检查 node 非空，再访问 node.next

思考题

为什么链表题几乎都需要 dummy 节点？什么时候可以不用？

当头节点可能被删除或更换时（如合并、删除、反转），没有 dummy 就要对头节点特殊判断。如果确定头节点不会变（如只是遍历或修改值），可以不用 dummy。

K 个一组反转中，为什么要先检查后续是否还有 k 个？

题目要求不足 k 个的尾部保持原序。如果不先检查就反转，最后一组不足 k 个也被反转了，不符合要求。先数 k 个确认够了再反转。

如何不用额外空间判断链表是否为回文？

组合三个操作：(1) 快慢指针找中点 → (2) 反转后半段 → (3) 双指针从头和中间同时比较。用到了找中点 + 反转两个核心操作。
