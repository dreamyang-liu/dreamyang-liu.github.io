Backtracking Template

2023-09-02
Backtracking

Backtracking = DFS on a decision tree: choose → recurse → undo. Every “enumerate all possibilities” problem uses the same template; the only difference is how you build the “choices list”.

Intuition

Imagine standing at every fork in a maze doing one thing: place a small stone to mark “I came from this path”, then walk forward; when you hit a dead end or find an answer, retrace your steps and pick up the stone. That stone-pickup step is “backtracking” — it lets you reuse the same path list over and over, instead of copying the state at every level.

So backtracking has exactly three actions:

  1. Make a choice: path.append(c)
  2. Recurse: enter the next level
  3. Undo: path.pop()

Step 3 is symmetric to step 1. Miss one, and the state gets dirty; add an extra one, and the result is wrong.

The Decision Tree Is the Core

Subsets, permutations, combinations, partitions, N-queens, sudoku — they look very different, but once you draw the “decision tree”, you’ll see: backtracking is always DFS on a tree; only the shape of the tree differs.

  • Subsets: each level decides “include/exclude the current element”; every node is an answer (leaves and internal nodes alike)
  • Permutations: each level picks one from “what’s left unused”; collect only leaves, needs used[]
  • Combinations: each level picks from start onward, avoiding duplicates; collect only leaves, needs start

Click [Next Step] to watch how path evolves as the DFS advances: choose 1 → path=[1], then choose 2 → path=[1,2], hit the bottom → copy snapshot into ans, then pop back to [1], continue to the sibling node. The second animation places permutations and combinations side by side so you can visually see: permutations branch to “all remaining” at every internal node, combinations only branch to “elements further right”, so one tree is fat and full, the other narrow and lean.

Template

Lock in this snippet — every variant just changes “choices” and the termination condition:

Three pairs of operations that must be symmetric:

  • path.append ↔ path.pop
  • used[i] = True ↔ used[i] = False
  • Any “mark dirty” state modification ↔ restore

Three Problem Families

Problem choices When to collect Count
Subsets range(start, n) every node
Permutations all + filter via used[] leaves (len==n)
Combinations range(start, n) leaves (len==k)

Quick mnemonic: subsets collect all nodes, permutations use leaves + used, combinations use leaves + start.

Deduplication Pattern

When there are duplicate elements, sort first, then skip duplicate values at the same level:

Why i > start and not i > 0? Because we want sibling deduplication, not parent-child deduplication — i == start is the first choice at this level; if it equals “the previous one”, that previous one is actually a parent node, not a sibling, so we must not skip it.

Common Pitfalls

  • Forgetting path[:] — ans ends up full of references to the same list, which is empty after backtracking completes
  • Asymmetric append/pop — missing one pop causes state contamination
  • Using start for permutations or used for combinations — the decision tree shape is simply wrong
  • Forgetting to sort before deduplication — i > start && nums[i]==nums[i-1] won’t work
  • path.append before the recursive call but pop in the wrong position, corrupting state before recursion finishes

Complexity

Time complexity = number of decision tree nodes × work per node. The worst case is determined by leaf count: permutations , subsets , combinations . The extra factor of or comes from the path[:] copy.

One-sentence summary: Backtracking isn’t an algorithm — it’s the codification of “DFS on a decision tree while restoring state”. Draw the tree and the template snaps into place.
