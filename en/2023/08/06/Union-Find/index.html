Union-Find (DSU)

2023-08-06
data-structures

Each set is represented by a tree, with its root as the representative. find walks up parent pointers to the root; union attaches one root under another. With path compression and union by rank, each operation is amortized — the inverse Ackermann function, practically , essentially .

Intuition — one tree per set

Imagine a group of people, each pointing to their “boss”. To ask “are A and B in the same group?”, both climb up their boss pointers until they reach someone who points to themselves (the gang leader / root). Same root → same group. To merge two gangs, make one boss acknowledge the other as their new boss. The entire data structure is just one array: parent[i] = i's parent, where root nodes satisfy parent[i] == i.

Two primitives:

  • find(x): walk up parent pointers and return the root of x’s set.
  • union(x, y): find both roots rx and ry; if they differ, set parent[rx] = ry.

The naive version can degenerate into a chain, making find . Two optimizations fix this:

  • Path compression: during find, on the way back up, attach every node on the path directly to the root — the tree gets flatter with use.
  • Union by rank: attach the shorter tree under the taller one to prevent chaining.

Used together, each operation is amortized .

Template — path compression only (sufficient for 90% of problems)

Three common mistakes:

  1. union must find both roots before merging — you can’t just do p[x] = y. That attaches a node directly, orphaning the rest of x’s original set. Only roots represent their entire set.
  2. Path compression goes inside find — don’t forget it. The recursive version is cleanest; the iterative version is slightly faster and doesn’t risk stack overflow.
  3. cnt decrements only when an actual merge occurs (rx != ry).

Advanced — union by rank / weighted union-find

Union by rank

In practice, path compression alone is enough. Only add union by rank when you need a rigorous complexity proof or the problem has tight constant-factor constraints.

Weighted union-find

Edges carry weights representing a relationship between two nodes (difference, ratio, distance, …). During find, accumulate edge weights along the path; during union, derive new edge weights from the known relationship.

Classic problem: LC 399. Evaluate Division — a/b = 2, b/c = 3, deduce a/c. Use “ratio” as the edge weight and multiply during find.

Three use cases — connectivity / component count / offline time-reversal

1. Check connectivity: two nodes with the same root → connected. Redundant connection (LC 684): add edges one by one; the first one that hits two nodes with the same root is the redundant edge.

2. Count connected components: the final uf.cnt is the answer. Number of Provinces (LC 547) and Number of Islands (LC 200) are direct templates.

3. Offline “time-reversal”: Union-Find only supports merging, not splitting. Problem asks you to delete edges / remove nodes? Read all operations first, then add edges in reverse from the final state — deletions become additions. Classic problem: LC 803. Bricks Falling When Hit.

The third use case is the key to “hard” interview problems — whenever you see “deletions in order”, immediately think about whether you can process it offline in reverse.

Classic problems

Warm-up (nail one, know the whole category):

  • LC 547. Number of Provinces — bare-bones component count
  • LC 200. Number of Islands — 2D grid mapped to 1D id (i*n+j)
  • LC 684. Redundant Connection — add edge, same root = answer
  • LC 990. Satisfiability of Equality Equations — process == first, then !=

Advanced:

  • LC 128. Longest Consecutive Sequence — union x with x+1
  • LC 399. Evaluate Division — weighted union-find template
  • LC 721. Accounts Merge — use emails as nodes, union all emails within the same account
  • LC 803. Bricks Falling When Hit — time-reversal classic
  • LC 685. Redundant Connection II — directed graph variant, requires case analysis

Memory aid

One sentence: Set is tree, root is representative; find finds the root, union joins roots.

Three things to memorize:

Item Key point
Data parent[] one-dimensional array; root satisfies p[i]==i
find Walk up parent pointers to root, attach to root on the way back (path compression)
union Find both roots first, join root to root, cnt -= 1

Quick decision guide:

  • “How many connected components / are these in the same group” → Union-Find
  • “Add edges in order” → online Union-Find
  • “Delete edges / nodes in order” → offline reverse + Union-Find
  • Edge has weight (ratio, difference) → weighted Union-Find

Get the template to the point where you can write it from memory in 30 seconds, and 90% of connectivity problems are just applying the template + figuring out “what are the nodes, and when do we union”.
