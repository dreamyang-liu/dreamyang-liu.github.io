1.2 Multi-Head Attention

Multi-Head Attention (MHA) projects the input into multiple different subspaces; each “head” independently computes attention, then the results are concatenated and projected back to the original dimension.


Why split into multiple heads?

  • Diversity: different heads can learn to attend to different types of relationships (syntactic, semantic, positional, etc.)
  • Computational efficiency: each head has dimension , so total computation is the same as a single large head
  • Expressiveness: attention patterns across multiple subspaces are richer than those in a single space

Typical configurations: GPT-3 uses 96 heads with , giving each head dimension 128. LLaMA-2-70B uses 64 query heads (plus 8 KV heads for GQA).

1.3 Flash Attention

Flash Attention is an IO-aware exact attention algorithm. Its core motivation: GPU compute is far faster than memory bandwidth. The bottleneck in standard attention is not FLOPs — it’s the number of HBM (High Bandwidth Memory) reads and writes.

Root Cause: HBM Access in Standard Attention

Every step of standard attention requires HBM reads/writes. Tracking shapes and HBM access volume for a single head:

Key bottleneck: The intermediate matrices S and P are both [N, N]. At N=4096, d=128: S[4096×4096] takes 32 MB, while Q/K/V each take only 1 MB — the intermediates are 32× larger than the inputs/outputs! We pay O(N²) extra memory and massive HBM traffic just to store temporary matrices.

Flash Attention’s Solution: Tiling + Online Softmax

Core idea: never write an N×N matrix to HBM. Tile Q, K, V into small blocks, and do all computation inside Shared Memory (programmer-controlled on-chip SRAM per SM; up to ~192 KB/SM on A100). Note this is distinct from L2 Cache (40 MB, hardware-managed) — Shared Memory is directly controllable.

Online Softmax Algorithm

Standard softmax requires two passes (pass 1 to find max; pass 2 to sum the exps), which demands that the full S matrix be materialized. Flash Attention uses an online algorithm that only needs a single pass. The animation below uses a 1×8 score vector (split into 4 blocks) to dynamically show how m, l, and O are updated block by block, and how old values are corrected by the correction factor α when a new block reveals a larger max:

Mathematical intuition: the attention output is fundamentally just numerator / denominator:

The online algorithm incrementally accumulates numerator and denominator, using a running max for numerical stability:

Intuition:

  • Relationship between O and l — l accumulates exp(score), O accumulates exp(score)×v, and at the end O/l is a softmax-weighted average; the update rules are perfectly symmetric.
  • Why do we need α = exp(m_old − m_new)? — After encountering a larger score, all previous exp(s − m_old) values need to become exp(s − m_new). Since exp(s − m_new) = exp(s − m_old) × exp(m_old − m_new), multiplying old values by α does the job.
  • What if the new block has no larger max? — m_new = m_old → α = 1 → old values stay unchanged, only new terms are added.
  • Mathematical equivalence — this is not an approximation! After iterating over all blocks, O/l is strictly equal to softmax(QKᵀ)V.

Metric Standard Attention Flash Attention Advantage
HBM read/write count Θ(Nd + N²) Θ(N²d²/M) reduced when M > d²

Numerical result exact exact (bit-identical) not an approximation!

Flash Attention is not an approximate algorithm! It produces bit-identical results to standard attention. The only difference is in the IO pattern: it trades more compute for fewer memory accesses (because GPU compute is far faster than memory bandwidth).

1.4 Cross Attention vs Self-Attention

The fundamental difference between self-attention and cross attention lies in where Q, K, V come from:

Property Self-Attention Cross Attention
Source of Q same sequence decoder sequence
Source of K, V same sequence encoder output
Typical use language modeling, BERT translation, vision-language
Causal Mask used in decoder typically not used
KV Cache grows each step fixed after encoding

Applications:

  • Self-Attention: GPT family (causal), BERT (bidirectional)
  • Cross Attention: machine translation (encoder-decoder), multimodal models (image tokens attend to text tokens), Stable Diffusion (text→image conditioning)

1.5 KV Cache

In autoregressive generation, computing attention for each new token naively requires recomputing the keys and values for all previous tokens. KV cache avoids this redundancy by caching the already-computed K and V matrices.

Why cache only K and V, not Q? Because during generation we only need the new token’s Q to attend over all previous K and V. The Q values of earlier tokens are no longer needed — their outputs are already determined:

The animation below generates tokens one by one: the left side shows the attention matrix (only computing the new row), the right side shows the KV cache growing, and the bottom compares compute cost with and without caching:

Memory footprint analysis: KV cache size = 2 (K+V) × num_layers × num_heads × head_dim × seq_len × dtype_size.

Example: LLaMA-2-70B (80 layers, 64 heads, head_dim=128, FP16) at seq_len=4096: KV cache = 2 × 80 × 64 × 128 × 4096 × 2 bytes ≈ 10.7 GB per request.

1.6 Special Tokens and Chat Templates

Modern LLMs use special tokens to mark sequence structure and control generation behavior. These tokens are defined at training time, and the model learns their semantics.

Token Purpose Example Models
<BOS> / <s> beginning of sequence LLaMA, Mistral
<EOS> / </s> end of sequence, stop generation LLaMA, Mistral
<PAD> pad to fixed length BERT, T5
<UNK> unknown token (OOV handling) most models
[INST]…[/INST] instruction markers LLaMA-2-Chat
<|im_start|> / <|im_end|> chat message boundaries ChatML format

Chat templates convert multi-turn conversations into token sequences the model can understand; the format varies across models:

Important: an incorrect chat template can severely degrade model output quality. Every model has an expected format that must be followed exactly. Using tokenizer.apply_chat_template() is the safest approach.

Role separation and attention masks: In a chat scenario, the system prompt is global context (all subsequent tokens can attend to it), the user turn is the user’s input, and the assistant turn is the model’s output. During SFT, cross-entropy loss is typically computed only on the assistant tokens; system and user tokens serve as context but do not contribute to the loss.

Exercise 4 (Bonus): Why is Prefill Compute-Bound and Decode Memory-Bound?

Arithmetic Intensity = FLOPs / Bytes Accessed.

Prefill: N tokens are processed simultaneously, forming large GEMMs. QKV projection AI ≈ 3000 FLOPs/byte, Attention AI ≈ 2730 FLOPs/byte — both >> H100’s compute/bandwidth ratio (~295) → compute-bound.

Decode: only 1 new token, but the entire KV cache must be read. FLOPs ≈ 67M, reads ≈ 64 MB → AI ≈ 1.05 FLOPs/byte << 295 → memory-bound; the GPU spends most of its time waiting for HBM to deliver the KV cache.

The AI difference between the two phases is ~3000×! This is why LLM serving systems distinguish prefill from decode (continuous batching, chunked prefill).
