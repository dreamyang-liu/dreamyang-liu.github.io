Algorithms Divide and Conquer

Finding the K-th element doesn’t require sorting the whole array. One partition call places the pivot at its final position, then you recurse only into the half where K lies. Expected — thoroughly beats sorting’s .

Intuition — Partition Is Enough; No Full Sort Needed

Sorting is because every level of recursion has to fully sort both halves. But finding the K-th element doesn’t care about the relative order of anything else — it only cares about one thing:

Whose final position is exactly K?

That’s precisely what partition produces. After one partition call, the pivot lands at its “correct sorted position” p, with everything to the left pivot and everything to the right pivot. Three cases:

  • p == k — return nums[p] immediately. Done.
  • p < k — the K-th element is in the right half; recurse there.
  • p > k — the K-th element is in the left half; recurse there.

Only one side is recursed, which is the fundamental reason quickselect beats quicksort by a log factor. The expected problem size halves each time: — a geometric series that converges. The worst case (always picking an extreme value as pivot) degrades to , but randomizing the pivot makes this statistically negligible.

Animation — Tracing the i/j Pointers Through Partition

The animation below runs on the array [3, 6, 2, 8, 1, 5, 4] with the last element 4 as pivot. Step through the Lomuto partition and watch two pointers:

  • Pointer i (green): marks “where the next element smaller than pivot should go” — everything left of i is < pivot.
  • Pointer j (cyan): the scanning pointer, inspects each element in turn.

The rule is just one line: if nums[j] < pivot, do swap(i, j); i++; otherwise just j++. After the scan, swap the pivot into position i and the partition is complete.

Read the template after watching the animation and every step will match up.

Template — Python (randomized pivot)

Three common mistakes:

  1. You must randomize the pivot. Without it, a sorted input causes every call to eliminate only one element, degrading to .
  2. k is 0-indexed. To find the K-th largest, convert with k = n - K; for the K-th smallest, use k = K - 1.
  3. Write it as while True + iteration, not recursion. Recursion can blow the stack in the worst case.

Three-Way Partition — Handling Many Duplicate Elements

If the array contains many elements equal to the pivot, Lomuto partition keeps cutting between them and degrades. Three-way partition (Dutch National Flag) splits the array into < pivot, == pivot, and > pivot segments; the equal segment is skipped entirely.

Determine which segment K falls in: k < lt → go left; k > gt → go right; otherwise nums[k] is the answer.

Quickselect vs. Heap for Top-K — Comparison

Two common misconceptions: “use a heap to find the K-th element” and “quickselect is always faster.” Neither is right. It depends on the situation:

Dimension Quickselect Heap
Time (expected)
Time (worst case)
Space in-place
Original array gets shuffled untouched
Data model offline (all data must be available) online / streaming
Multiple queries each time maintain one heap, per query

How to choose:

  • One-shot, offline, enough memory, large data → quickselect.
  • Streaming data, cannot modify the original array, need guaranteed worst-case complexity, → heap.
  • Extreme cases ( or ): a single linear scan beats everything.

Note that when , is practically (log k is a tiny constant), the heap code is also shorter, and in an interview setting writing the heap solution is usually the safer choice.

Classic Problems

  • LC 215. Kth Largest Element in an Array — pure template. Note: “K-th largest” → k = n - K.
  • LC 347. Top K Frequent Elements — count frequencies first, then quickselect (or heap) on the frequencies.
  • LC 973. K Closest Points to Origin — partition by squared distance; a standard application.
  • LC 324. Wiggle Sort II — quickselect for the median, then three-way partition + index mapping. Hard.
  • LC 462. Minimum Moves to Equal Array Elements II — median = element at index ; pull it out with quickselect, no sorting needed.

Memory Aid / Common Mistakes

One sentence: one partition places the pivot; only recurse into the side containing K.

Three-way comparison:

Problem Algorithm Complexity
Full sort quicksort (recurse both sides)
Find K-th element quickselect (recurse one side) expected
Maintain Top-K heap (min-heap of size K)

Checklist of common mistakes:

  1. K’s index: 0-indexed or 1-indexed, “K-th largest” or “K-th smallest” — sort this out before writing.
  2. Pivot must be randomized, or sorted input immediately gives .
  3. Partition returns pivot position p, not the value. You compare the indices p and k.
  4. Many duplicate elements → use three-way partition, otherwise it degrades.
  5. Don’t recurse — use while True + adjust lo/hi to avoid stack overflow.
  6. The original array gets shuffled. If the caller can’t tolerate that, copy it first.
