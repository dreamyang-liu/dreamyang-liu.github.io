2023-08-06
Binary Tree

Pre/in/post-order traversal are not three separate algorithms — they are the same recursive skeleton with the “print root” line placed at different positions. Recursion handles it in one line; iteration uses a stack to manually simulate the call stack. BFS swaps in a queue for level-order. Remember this and binary-tree traversal problems will never confuse you again.

Intuition — Pre/In/Post Only Differ in Root Position

Write the standard binary-tree recursive skeleton:

Where the root-visit statement sits relative to the two recursive calls (left, right) determines the traversal name:

Traversal Order Root position Good for
Pre-order Root → Left → Right Before both recursive calls Top-down parameter passing (path / prefix)
In-order Left → Root → Right Between both recursive calls BST sorted output
Post-order Left → Right → Root After both recursive calls Bottom-up aggregation (height / diameter)

Level-order is a different category: no recursion, use a queue instead, spreading outward layer by layer. It is fundamentally BFS.

Animation — Same 7-Node Tree, Three Orders

The complete binary tree below has 1 as the root and 4, 5, 6, 7 as leaves. Use the buttons on the animation to switch traversal modes and observe the visit order: pre-order dives left from the root, in-order starts from the bottom-left, and post-order reaches the root last. The difference in “root position” is immediately visible.

Key observation: the first node in pre-order is always the root; the last node in post-order is always the root; in in-order, the root’s position depends on the size of the left subtree. This is the foundation of why “pre-order + in-order uniquely determines a tree.”

Iterative — Using a Stack to Simulate the Call Stack

Why do we need a stack? The reason recursion can “descend into the left subtree and come back to handle the right subtree” is that the system call stack saves the current position for you. Applications — Three Must-Knows

1. BST In-Order = Ascending Order

BST definition: all left subtree values < root < all right subtree values. In-order “left-root-right” unfolds this partial order into a total order. Validating a BST, finding the k-th smallest, range sum queries — all of these rely on this single fact.

2. Pre-Order + In-Order → Unique Construction

The first element of pre-order is the root. Use that root to split in-order: everything to the left is the left subtree’s in-order, everything to the right is the right subtree’s in-order. Recurse and the tree is built.

Note: pre-order alone, in-order alone, or post-order alone cannot uniquely determine a tree. You need in-order paired with either pre-order or post-order.

3. Morris Traversal — O(1) Space

Recursive traversal uses O(h) stack space; iterative also uses O(h). Morris traversal reduces extra space to O(1) — at the cost of temporarily modifying the tree.

Core idea: when the current node cur has a left subtree, find the rightmost node of that left subtree (the in-order predecessor) and point its right pointer at cur (the “thread”), so we can “fly back” to cur from the deepest point of the left subtree. After visiting cur, remove the thread and restore the tree.

Interview problems rarely ask you to code this, but they often ask “how do you traverse in O(1) space?” — answer: Morris.

Classic Problems

LC Problem Which traversal
104 Maximum Depth of Binary Tree Post-order (get subtree depth)
226 Invert Binary Tree Pre- or post-order both work
98 Validate BST In-order (check ascending)
543 Diameter of Binary Tree Post-order (left depth + right depth)
124 Binary Tree Maximum Path Sum Post-order + two values: “through me vs. give to parent”
236 Lowest Common Ancestor Post-order (search left and right, then check root)
105 Construct Tree from Pre- and In-order Pre-order pins root, in-order cuts left/right
102 Level Order Traversal BFS + len(q) for layer separation
297 Serialize and Deserialize Binary Tree Pre-order (with nulls) is most natural

Quick rule for choosing: if the answer at the current node needs return values from subtrees → post-order; needs top-down parameter passing → pre-order; BST property → in-order; process layer by layer → level-order.

Memory Aids

  • The only difference among the three traversals is one line: where you place the print-root call — before / between / after the two dfs(left) and dfs(right) calls.
  • Recursion in one line, iteration needs a stack: the stack manually simulates the call stack, explicitly saving “what to do next.”
  • Stack ↔ DFS, Queue ↔ BFS: swap the data structure and depth becomes breadth. Level-order’s len(q) is what makes it truly “layer-by-layer.”
  • Pre-order + In-order = unique tree: pre-order pins the root, in-order cuts left and right, recurse.
  • BST in-order = ascending: whenever BST sorted order is involved, think in-order first.
  • O(1) space traversal = Morris: use the empty right pointer of the leaf as a temporary thread; remove it after visiting.

One-line summary: binary-tree traversal = recursive skeleton + one line for root position; iteration unrolls the recursive stack; level-order swaps the stack for a queue.
