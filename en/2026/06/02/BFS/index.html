BFS (Breadth-First Search)

2026-06-02
Graph Theory Search

One sentence: BFS = treat the graph like a pond, drop a stone at the start, and watch the ripples expand outward ring by ring. The first ring that reaches the target is the shortest number of steps (unit edge weights).

Intuition

Imagine you’re standing at the entrance of a maze and shout into it. Sound doesn’t “pick one path and go deep” — it fills the current ring of air simultaneously, then the next ring. BFS is exactly this propagation process written as code:

  • Current wavefront (nodes in the queue) = all nodes exactly steps from the start
  • Next wavefront = all neighbors of the current wavefront (excluding already-visited ones)
  • The at which the target first gets swept into the wavefront is the answer

DFS is “go as deep as possible down one path before backtracking”; BFS is “march in step, advance simultaneously”. Whenever the question is “fewest steps”, it’s almost always BFS.

Template (memorize this one)

Three non-negotiable details (get any one wrong and you get WA or TLE):

  1. for _ in range(len(q)) — freeze len(q) first, then loop. Otherwise you’re dequeuing and enqueuing simultaneously and can’t tell which nodes belong to the current layer.
  2. visited.add(nxt) at enqueue time, not dequeue time. Marking at dequeue time means the same node gets pushed by all 4 neighbors, causing queue bloat (the animation makes this very visible: relax this constraint and the orange cells keep flashing repeatedly).
  3. step += 1 goes outside the for loop, not inside. step is a layer number, not a node number.

Multi-Source BFS

More than one starting point? Push all of them into the initial queue at once. This is equivalent to adding a virtual super-source outside that connects to every start with edge weight 0. The template doesn’t change at all — just change the initialization.

Classic problems: Rotting Oranges (animation 2), 01 Matrix (distance to nearest 0).

0-1 BFS

Edge weights are only 0 or 1. Replace the plain queue with a deque: weight-0 edges use appendleft, weight-1 edges use append. O(V+E) instead of Dijkstra’s O(E log V).

Bidirectional BFS

Expand from both start and end simultaneously; each round always expand the smaller frontier, return when the two sides meet. Search space drops from to — exponential halving. Requirements: target is known, neighbors can be reversed. Typical problems: 127 Word Ladder, 752 Open the Lock.

BFS vs DFS — How to Choose

  • Fewest steps / minimum operations → BFS
  • All paths / permutations & combinations / connected component size → DFS
  • Topological sort → either works (Kahn’s is BFS)

Memory Aid & Common Pitfalls

Remember three images:

  1. Pond ripples — the essence of BFS. The ripple radius at which the target is first reached = the answer.
  2. Frozen len(q) — the only way to distinguish “this layer” from “the next layer”.
  3. Mark at enqueue — not at dequeue, not at dequeue, not at dequeue.

Common traps:

  • Putting step += 1 inside the inner for loop → answer becomes “how many nodes were visited”, wildly wrong.
  • Using BFS when edge weights aren’t 1 → wrong answer. Use Dijkstra or 0-1 BFS.
  • Forgetting bounds checking in grid problems → IndexError or wrapping to the other side.
  • Using BFS for “can we reach this node?” → not wrong, but wasteful; DFS is shorter to write. BFS is only mandatory when you need the shortest path.

Exercises

Why can BFS guarantee the shortest path (when edge weights are 1)?

Layer-by-layer expansion ensures that nodes at layer are exactly distance from the start (no less: if they were closer, an earlier layer would have visited them; no more: adjacent layers differ by 1). The layer number when the target is first visited is the shortest distance.

What's the difference between "mark at enqueue" vs "mark at dequeue"?

Mark at enqueue: each node enters the queue at most once; queue size = O(V).
Mark at dequeue: the same node can be pushed multiple times by different neighbors (in a grid, all 4 directions might push the same cell), bloating the queue to O(E), wasting both time and space. Both approaches produce correct results, but the latter frequently TLEs.

When is bidirectional BFS applicable?

Requirements: both start and end are known + neighbors can be traversed in reverse. Exponentially shrinks the search space ().
Not applicable: target is unknown (e.g., “find the farthest node”), neighbors are one-directional (directed graph with no reverse graph available).
