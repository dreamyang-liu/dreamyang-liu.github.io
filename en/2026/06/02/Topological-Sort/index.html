Topological Sort

2026-06-02
Graph Theory Topological Sort

Order all nodes in a DAG so that every edge points from an earlier node to a later one. Know both implementations by heart: Kahn’s algorithm (BFS in-degree method) and DFS post-order reversal. Cycle detection comes for free.

Intuition — “First Come First Served” on a DAG

Topological sort solves exactly one problem: given a bunch of tasks with dependencies, find an order that lets you complete them one by one.

More formally: given a directed acyclic graph (DAG), arrange all nodes in a line so that for every edge u → v, u appears before v.

Analogies:

  • Course prerequisites: prerequisite courses come before the courses that depend on them.
  • make build system: targets that are depended on get compiled first.
  • Task scheduling: predecessor tasks execute first.

The critical requirement is no cycles. With a cycle it’s impossible to say who comes first, which is why topological sort naturally doubles as a DAG validator.

Two Implementations — Kahn (BFS) and DFS Post-Order

Kahn’s Algorithm — Push Zero-In-Degree Nodes Into the Queue

One sentence: count in-degrees; push all nodes with in-degree 0 into the queue; each time you pop a node, decrement its neighbors’ in-degrees, and re-enqueue any that hit 0.

Intuitive, controllable, easy to adapt. To get the lexicographically smallest topological order, swap deque for a min-heap (heapq).

DFS Post-Order Reversal — Stack-Exit Order Is Topological Order

One sentence: once DFS finishes a node, push it onto a stack; reversing at the end gives topological order.

Why does reversing post-order give topological order? Because before node u exits the stack, all of its successors have already exited. Nodes that exit later must come earlier in the final order, so we flip at the end.

Which One to Choose

Scenario Choose
Stable, controllable, layer-by-layer processing Kahn
Lexicographically smallest order Kahn + min-heap
Shorter code / also need SCC DFS
Reverse topological order (DAG DP from sinks) DFS (post-order is already reverse topo)
Very large graph, worried about recursion stack overflow Kahn

Free Cycle Detection — Using Topological Sort to Validate a DAG

Cycle detection is a byproduct of topological sort — both implementations include it for free, no separate algorithm needed.

Kahn’s method: after the run, check len(order). If < n, some nodes have an in-degree that never reached 0 — they’re stuck in a cycle → cycle exists.

DFS method: gray meets gray means a cycle in three-color marking. Gray means “currently on the DFS path”; encountering a gray node again means we’ve walked back to ourselves, forming a back edge.

Two reminders:

  1. You can’t use topological sort to detect cycles in an undirected graph (undirected graphs have no “in-degree” concept). Use union-find or DFS checking for non-parent visits instead.
  2. If you only need to detect a cycle without outputting the order, Kahn’s method can just keep a counter instead of storing order, saving some memory.

Classic Problems — Course Schedule / Task Scheduling

LC 207. Course Schedule: given numCourses and prerequisites [[a, b], ...] (you must take b before a), determine whether you can finish all courses. This is essentially just validating a DAG.

LC 210. Course Schedule II: same graph, output the course order. Replace done += 1 with order.append(u), then return order if len(order) == n else [].

Classic trap: edge direction. The problem says “you must take b before a”, meaning b is the prerequisite for a, so the graph edge should be b → a (b before a). Reversing the direction and getting WA is a rite of passage.

Other must-solve problems:

  • LC 802. Find Eventual Safe States — reverse graph + topological sort; safe = all paths terminate
  • LC 269. Alien Dictionary — build edges from the first differing character of adjacent words, run topo sort
  • LC 310. Minimum Height Trees — topo-sort-like, peel leaf nodes (degree=1) each round; the last 1–2 nodes are the answer
  • LC 329. Longest Increasing Path in a Matrix — DP on a DAG, can use memoized DFS or topological DP
  • LC 2192. All Ancestors of a Node in a Directed Acyclic Graph — merge ancestor sets in topological order
  • LC 1857. Largest Color Value in a Directed Graph — topological order + color-count DP, cycle detection included

Memory Aid

One sentence: zero in-degree goes first; each departure trims one edge.

Three contrasts:

Dimension Kahn (BFS) DFS Post-Order
Entry Nodes with in-degree 0 enqueued Any unvisited node, DFS
Progress Dequeue → decrement neighbor in-degrees Recurse to bottom → exit stack
Cycle detection Output count < n Gray meets gray
Order Topological order falls out naturally Reverse the post-order array

Recognition cheat sheet:

  • See “prerequisite”, “dependency”, “predecessor task” → topological sort.
  • Problem asks “can you finish?” → cycle check is enough; use Kahn’s counter.
  • Problem asks “output the order” → Kahn storing order, or DFS post-order reversed.
  • Requires “lexicographically smallest” → swap Kahn’s deque for heapq.
  • DP on a DAG → iterate in topological order; predecessors are already computed, just transition.

One thing to remember: topological sort is not a sorting algorithm — it’s a dependency resolution algorithm. The “order” it produces is one valid execution sequence and may not be unique.
